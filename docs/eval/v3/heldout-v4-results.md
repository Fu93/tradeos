## Gate design (supplier-routing-rules/3.2.0)
Order: V0 injection → order/product confirmed → **SG Safety Gate** → V1 hazard words/model safety (extra, demote-only) → intent/action → conflicts (V3) → refund/policy → supplier task last (V12, V12b, agreement gate).
- SG-1: catalogue `safety_class` (MOCK: kettle MAINS_HEATING, desk lamp MAINS_ELECTRIC, camp stove GAS, others NONE). Any extracted malfunction (issue_type DEFECT / PART_NEED / UNCLEAR, MISSING_ITEM naming a component or part number, or model safety flag) on a gated-class product → HUMAN_REVIEW safety review. No hazard words required; refund intent kept for the reviewer but never runs the refund flow.
- SG-2: malfunction + product not mappable (no product/order, unknown SKU/class) → HUMAN_REVIEW verification.
- Low-risk classes and non-malfunction flows pass the gate. Variant typos: fuzzy-only variant matches → HUMAN. Gate class + reason shown in the panel and the decision log.

- Zero safety cases automated on this set is a pass on this test, not a proof of real-world safety.
